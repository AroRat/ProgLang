### Задание 4 **(2)** ✅
*Рассмотрим следующий пример в IDLE Python*
```
>>> x = 99.99
>>> int(x/10+0.001)
9
```
*Результат должен был быть равен 10, однако оказался другим. Почему так произошло?
Как исправить программу, чтобы она корректно переводила вещественные числа в целые?*

---

Дело в том, что само число записывается в память с погрешностью (99.98999...). При
сумме получается 9.999, а так как у нас приведение в int, то дробная часть просто отбрасывается.

Для решения проблемы используется округление round().
```python
x = 99.99
print(int(round(x / 10, 0)))
```


### Задание 5 **(2)** ✅🟨
*Рассмотрите следующую программу. Объясните результаты ее работы. В частности,
как величина* $y$ *повлияла на ответ?*
```
x = 1/3
y = 1
for i in range(20):
    print((x+y)-y)
    y*=10
```
*В отчете требуется привести вычисления для оценки погрешности.*

---

Значение 1/3 в переменной x будет с погрешностью ($0.[3]_{10}$, $11.0[1001]_2$). По мере роста y (примерно с $y = 10^{14}–10^{15}$) младшие
значащие цифры начинают искажаться из-за накопления погрешности округления, и начиная с $y=10^{16}$ и далее до конца цикла (до $y=10^{19}$),
программа начинает выводить 0.0.

1. При $y≪x$ число $y$ занимает очень мало бит в мантиссе, поэтому для хранения суммы остается много места. Погрешность минимальна, результат близок к истинному 1/3.
2. При $y≫x$, когда $y$ становится огромным (например, $10^16$), все доступные 52 бита мантиссы уходят на хранение самого числа $y$. Маленькое число $x$
(1/3≈0.333) оказывается меньше минимального шага дискретности для данного порядка числа $y$. Компьютер физически не может вместить такое маленькое добавление
рядом с гигантским числом.


### Задание 6 **(2)** ✅
*Для какого минимального значения* $n$ *программа на С++ выведет* **inf**? *Объясните
ответ.* *Что произойдет, если тип* **double** *заменить на* **long double**?
```
int n=...;
double s = pow(2, n);
std::cout << std::fixed << s << std::endl;
```
---
1. Минимальное значение n - 1024.  
В IEE 754-2008 под экспоненту выделяется 11 бит (от -1022 до 1023). На второй строке значение всё ещё помещается в double и получается $8.98 * 10^{37}$.
Когда n становится равным 1024, результат превышает максимальное конечное число, которое может вместить double (превышается максимальный порядок).
Происходит арифметическое переполнение и переменная s принимает специальное зарезервированное значение inf.
2. Поведение зависит от компилятора.  
В случае с GCC границы экспоненты расширятся (показатель степени доходит до 16383) и программа выведет точный результат.

### Задание 8 **(2)** ✅
*Какое минимальное натуральное число при преобразовании в тип* **double** *записывается с погрешностью? Объясните
ответ. Почему следующее за ним число уже выводится без погрешности?*

---

Минимальное число - $2^{53}+1$. В стандарте IEE 754 под мантиссу выделяется 52 бита. Это число требует уже 54 бита памяти.
Так как 54-й бит физически не помещается в мантиссу double, число приходится округлять до ближайшего представимого значения, что и порождает погрешность.

Как только число достигает $2^{53}$, шаг между соседними представимыми значениями увеличивается до 2. Четные числа ($2^{53}+2=9007199254740994$) попадают ровно на "сетку" доступных значений double и сохраняются абсолютно точно.
